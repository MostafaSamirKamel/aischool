# AI School — بوابة الطالب | Student Frontend

واجهة الطالب كاملة، مصممة بتجربة Mobile App للهواتف وDashboard للكمبيوتر.

## التشغيل

### معاينة بدون تثبيت أي شيء
افتح الملف المنفصل `AI_School_Student_Frontend_Preview.html` المرفق خارج مجلد المشروع. المعاينة تعرض **بيانات تجريبية وهمية** بوضوح، ويمكن إخفاؤها من الشريط العلوي. لا تتضمن أي بيانات طالب حقيقي.

### تشغيل المشروع من المصدر

```bash
cd AI_School_Student_Frontend
python -m http.server 8080
```

افتح `http://localhost:8080`؛ سيبدأ المشروع بحالة بيانات فارغة. اضغط «تجربة ببيانات توضيحية» إن أردت تجربة التنقل والمحتوى.

ليس هناك تثبيت npm أو bundler أو مكتبات تشغيل مطلوبة. واجهة المشروع مكتوبة بـHTML/CSS/JavaScript ويمكن تقسيم صفحاتها لمكوّنات React إذا كان تطبيقكم الحالي يعتمد React.

## الملفات

- `index.html` نقطة الدخول.
- `styles.css` الهوية الكاملة، تصميم الهاتف والكمبيوتر، الوضع الفاتح والداكن، والطباعة.
- `js/app.js` كل صفحات الطالب، تفاصيل الكورس، النوافذ، التنقل والبحث والوظائف التجريبية.
- `js/demo-data.js` **بيانات توضيحية منفصلة تمامًا** ولا تُحمّل افتراضيًا عند فتح المشروع.
- `js/api.js` طبقة REST API جاهزة للتوصيل.
- `manifest.webmanifest`, `sw.js`, `assets/` بنية PWA الأساسية (التثبيت يتطلب HTTPS وخادمًا مناسبًا).

## الصفحات

1. `/dashboard` الرئيسية: ترحيب، أقرب سيشن، كورسات، واجبات، امتحانات، تنبيه الأقساط، بورتفوليو، كل الخدمات.
2. `/reviews` تقييمات المدرسين وإضافة/تعديل تقييم في **وضع المعاينة فقط**.
3. `/enrollments` تسجيلات الطالب وسعر الكورس والخصم والمدفوع والمتبقي.
4. `/courses` كورساتي ومجموعاتي، حسب الحالة: نشط/مكتمل/موقوف/ملغي.
5. `/course/:id` تفاصيل الكورس، قائمة السيشنات، مصادر، واجبات، امتحانات، حضور ورسائل.
6. `/resources` مصادر تعليمية مع اختيار الكورس والبحث.
7. `/exams` الامتحانات والدرجات، وتجربة اختبار محلية وهمية (ليست تسليمًا حقيقيًا).
8. `/assignments` الواجبات والتفاصيل وتجربة واجهة رفع الملف (لا يتم رفع الملف).
9. `/payments` ملخص الحساب، سجلات الدفع والأقساط المستحقة والمتأخرة.
10. `/messages` رسائل المجموعات وإعلاناتها.
11. `/attendance` سجل الحضور ونسبة الحضور حسب كل مجموعة.
12. `/reports` التقرير الأكاديمي والرسوم البيانية والتصدير CSV و PDF بواسطة الطباعة.
13. `/services` كل الخدمات في قائمة مستقلة من الرئيسية.
14. `/profile` حسابي، بيانات الطالب، المظهر، الإشعارات.
15. `/search` البحث العام في بيانات الطالب.

> التنقل داخل تطبيق المعاينة عبر روابط `#` لتعمل المعاينة على الاستضافة الثابتة أو محليًا. يمكن ربط المسارات مع React Router أو الـRouter القائم حاليًا وقت الدمج.

## ربط الـBackend

افتح `js/api.js` وحدد `apiBaseUrl` على عنوان السيرفر، وإذا لزم غيّر `portalEndpoint`. مثال:

```js
window.AISchoolConfig.apiBaseUrl = 'https://api.example.com';
window.AISchoolConfig.portalEndpoint = '/api/student/portal';
```

أو عدّل كائن `window.AISchoolConfig` في ملف API مباشرة.

### طلب البيانات

`GET /api/student/portal` باستخدام جلسة المستخدم الموثّقة `credentials: include`. يجب أن يرجع كائنًا، بشكل مباشر أو داخل `data`:

```json
{
  "student": {"id": "student-id", "displayName": "...", "studentCode": "...", "email": "...", "phone": "..."},
  "notifications": [],
  "courses": [],
  "registrations": [],
  "teacherReviews": [],
  "resources": [],
  "exams": [],
  "assignments": [],
  "payments": [],
  "installments": [],
  "messages": [],
  "attendance": []
}
```

كل مجموعة بيانات اختيارية ويُتعامل مع غيابها كقائمة فارغة؛ لا يُضاف أي طالب افتراضي تلقائيًا. راجع `js/demo-data.js` لأسماء الحقول التفصيلية، وليس كمصدر فعلي للبيانات.

### قاعدة حالة الكورس المعتمدة

حالة اشتراك `canceled`/`paused` لها الأولوية، أما المجموعة التي أغلقها المسؤول `groupStatus: "closed"` فتظهر حالتها «مكتمل» حتى لو لم يكتمل حضور الطالب. **لا يتم تعديل حضور الطالب أو تقدمه** عند إغلاق المجموعة.

### أمان البيانات والإجراءات

- يجب اشتقاق هوية الطالب من جلسة التوثيق على السيرفر، **لا من studentId موجود داخل كود الواجهة أو Query String**.
- لا تعرض الـAPI بيانات طلاب آخرين، ويجب التحقق من صلاحية وصول الطالب للكورس والمجموعة والامتحان والملفات في السيرفر.
- الطلاب لا يغيرون المدفوعات أو الأقساط من الواجهة؛ التسويات في نظام الإدارة فقط.
- بدء الامتحان والتسليم النهائي والوقت والمحاولات والدرجات يتم تحديدها وحسابها والتحقق منها **في السيرفر**؛ لا تُرسل الإجابات الصحيحة ضمن الـAPI إلى المتصفح.
- واجهة رفع الواجبات في المعاينة تعمل بدون رفع فعلّي. استعمل `multipart/form-data` عبر نقطة API محمية عند التكامل، مع فحص النوع والحجم والفيروسات.
- حفظ التقييمات في المعاينة محليًا فقط. عند التكامل، اربط عمليات إنشاء/تعديل التقييم بصلاحية الطالب في السيرفر.
- بيانات الجلسة الحساسة يجب أن تستخدم Cookies من نوع HttpOnly + Secure + SameSite، مع CSRF protection عندما يلزم. لا تضف tokens إلى الملف المصدري.
- بيانات الأقساط في الرسوم توضيحية. يجب أن يحدد السيرفر الأرصدة الحقيقية، الخصومات، الإعفاءات، والمدفوعات التي تم اعتمادها.

### قواعد الحساب المعتمدة في الواجهة

- الحضور: سجلات الطالب المسجلة فقط، والمجموعة دون حصص تبقى «—» بدل وصفها بضعيفة.
- المتأخر: التاريخ الحقيقي إذا كان أقدم من اليوم وحالة القسط غير مسددة؛ مدة التأخير لا تظهر بالسالب.
- إجمالي المال في المعاينة مشتق من مبلغ التسجيلات وخصوماتها والمدفوعات. **عند الدمج المالي النهائي يُفضّل أن يرسل الـBackend ملخص الأرصدة المعتمد** بدل الاعتماد على تجميع مبسط من أحداث الدفع.
- كل المحتوى القادم من الـAPI يتم إخراجه كنص مُطهّر داخل DOM لتقليل XSS.

## ما تم تنفيذه كتفاعل تجريبي

البحث، الانتقال بين الصفحات، فلترة الكورسات والامتحانات والواجبات، تغيير الوضع الليلي، صفحات تفاصيل الكورسات والسيشنات، فتح المراجع، عرض إشعارات وتفاصيل حضور، إضافة/تعديل تقييم تجريبي، اختبار بسيط وحساب نتيجة توضيحية، محاكاة واجب دون رفعه، تصدير CSV والطباعة PDF.

**لا توجد مدفوعات أو تسليمات أو تقييمات تكتب على السيرفر في هذا الإصدار.** تفعيل العمليات الحقيقية يتطلب توصيل نقاط API والتوثيق.
