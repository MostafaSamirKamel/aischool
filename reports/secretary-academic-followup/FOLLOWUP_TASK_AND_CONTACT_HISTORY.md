# AI SCHOOL — SECRETARY ACADEMIC FOLLOW-UP CENTER
## 06 — FOLLOW-UP TASK & CONTACT HISTORY (تقرير مهام المتابعة والسجل الزمني للتواصل)

**تاريخ التقرير:** 20 أكتوبر 2026  
**المجال الإداري والتنفيذي:** دورة حياة مهام المتابعة وسجل التواصل التعاقبي  
**النماذج البرمجية:**
- `App\Models\StudentFollowUpTask`
- `App\Models\StudentFollowUpContact`
- `App\Services\AcademicFollowUpService`

---

### 1. القاعدة الحاكمة: الرصد التلقائي، والإنشاء اليدوي للمهام

> [!IMPORTANT]
> **قاعدة أعمال معتمدة نهائياً:**  
> رصد حالة التأخر يتم **تلقائياً** بواسطة النظام فور تجاوز الموعد النهائي.  
> ولكن إنشاء مهمة المتابعة يتم **يدوياً** وبشكل حصري بواسطة السكرتيرة المصرح لها.  
> **لا يتم تشغيل أي وظيفة مجدولة (Cron Job / Scheduled Task)** لإنشاء مهام متابعة تلقائية بمجرد فوات موعد الواجب أو الامتحان، تجنباً لإغراق لوحة التحكم بمهام غير مدروسة.

---

### 2. الحماية من تكرار المهام النشطة (Duplicate Task Prevention)

قبل إنشاء أي مهمة متابعة جديدة، يقوم النظام بفحص الجدول `student_follow_up_tasks`:
1. التحقق من وجود مهمة نشطة (`status IN ('pending', 'in_progress')`) لنفس:
   - الطالب (`student_id`).
   - نوع النشاط (`source_type = 'exam' / 'homework'`).
   - معرف النشاط (`source_id`).
2. **الإجراء عند وجود مهمة سابقة:**
   - يمنع النظام إنشاء مهمة جديدة مكررة.
   - يعيد النظام فتح المهمة القائمة تلقائياً، ويتيح للسكرتيرة تسجيل محاولة تواصل جديدة فورا.

---

### 3. بنية جدول وسجل التواصل التعاقبي (`StudentFollowUpContact`)

تم إنشاء الجدول المستقل `student_follow_up_contacts` لتوثيق كل مكالمة أو رسالة في سجل منفصل، مع الحقول التالية:

| الحقل البرمجي | النوع | الوصف والأهمية |
|---|---|---|
| `task_id` | Foreign ID | الربط مع مهمة المتابعة الرئيسية في `student_follow_up_tasks`. |
| `student_id` | Foreign ID | معرف الطالب المعني بالمتابعة لسهولة الاستعلام المستقل. |
| `contacted_guardian_id` | Foreign ID | معرف ولي الأمر الذي تم التواصل معه (إن وُجد). |
| `contact_method` | Enum/String | وسيلة التواصل: `phone_call` (اتصال هاتفي), `whatsapp` (واتساب), `sms`, `in_person`. |
| `contact_result` | Enum/String | نتيجة التواصل: `contacted`, `no_answer`, `unreachable`, `promised_submission`, `follow_up_required`, `resolved`. |
| `notes` | Text | تفاصيل ما دار في المكالمة أو نص الاتفاق مع ولي الأمر. |
| `next_follow_up_date` | Date/Nullable | موعد الاتصال القادم إذا طُلبت إعادة التواصل. |
| `contacted_by` | Foreign ID | معرف الموظف أو السكرتيرة التي أجرت الاتصال الفعلي. |
| `contacted_at` | Timestamp | التاريخ والوقت الدقيق لإجراء المكالمة. |

---

### 4. حماية السجل الزمني من التعديل (Append-Only Chronological Timeline)

```
[ 20 أكتوبر - 11:30 صباحاً ]
الموظف: منى عادل (سكرتيرة)
الوسيلة: اتصال هاتفي | النتيجة: لم يرد
الملاحظة: تم الاتصال مرتين على هاتف ولي الأمر ولم يتم الرد، وسيعاد الاتصال لاحقاً.
       │
       ▼
[ 21 أكتوبر - 01:15 ظهراً ]
الموظف: منى عادل (سكرتيرة)
الوسيلة: رسالة واتساب | النتيجة: تم التواصل
الملاحظة: تم التواصل مع والد الطالب وأكد أن الطالب مريض وسيقوم برفع الواجب الليلة.
       │
       ▼
[ 22 أكتوبر - 10:00 صباحاً ]
الموظف: منى عادل (سكرتيرة)
الوسيلة: مراجعة الواجب | النتيجة: تم حل المشكلة
الملاحظة: تم التأكد من رفع الطالب للواجب بنجاح وإغلاق مهمة المتابعة.
```

- يضمن النظام بقاء كل سجل تواصل محفوظاً كما هو دون إمكانية استبداله أو الكتابة فوقه (`Never Overwrite History`).
- تسجيل مكالمة ناجحة لا يغلق المهمة تلقائياً، بل يلزم السكرتيرة باتخاذ إجراء إغلاق صريح (`markCompleted`) عند التأكد التام من زوال سبب المتابعة.
