**Status:** Enforced & Fully Verified Across Stack

---

## 1. Principle of Separation of Powers

In accordance with strict academic administrative requirements, **permission to edit an enrollment does NOT grant permission to transfer a student's educational group**.

- **Enrollment Editing (`update_enrollments` / `Update:Enrollment`):** Allows an employee to update administrative notes, discount codes, payment plan metadata, or contact information.
- **Group Transfer (`transfer_student_group`):** A sensitive academic operation that alters classroom rosters, instructor assignments, attendance schedules, and learning resource contexts.

An employee holding only `update_enrollments` must be strictly prevented from altering `group_id`, both through the UI and via direct backend submission.

## 2. Permission Architecture & Seeding

### 2.1. Database Seeding & Migration
The permission was provisioned via database migration `database/migrations/2026_10_20_000002_create_student_group_transfers_table.php`:
```php
$permission = Permission::firstOrCreate([
    'name' => 'transfer_student_group',
    'guard_name' => 'web',
]);

// Seeded by default to high-level administrative roles
foreach (['super_admin', 'admin'] as $roleName) {
    $role = Role::where('name', $roleName)->first();
    if ($role && !$role->hasPermissionTo('transfer_student_group')) {
        $role->givePermissionTo('transfer_student_group');
    }
}
```

### 2.2. Policy Implementation (`EnrollmentPolicy.php`)
```php
public function transferGroup(User $user, Enrollment $enrollment): bool
{
    // Super Admin or users with explicit transfer_student_group permission
    if ($user->hasRole('super_admin') || $user->can('transfer_student_group')) {
        return true;
    }

    return false;
}
```

## 3. Defense-in-Depth Enforcement Layers

| Layer | Component | Security Mechanism | Unauthorized Outcome |
|---|---|---|---|
| **Frontend UI** | `EnrollmentForm.php` | `->disabled(fn ($record) => !auth()->user()?->can('transferGroup', $record))` | Select dropdown is rendered read-only; user cannot select another group |
| **Page Lifecycle** | `EditEnrollment.php` | In `beforeSave()`: inspects if `$data['group_id'] != $this->originalGroupId` and validates `can('transferGroup')` | Throws `ValidationException` blocking the save operation |
| **Course Widget** | `EnrollmentCoursesWidget.php` | In `assignGroup` action: `->visible(fn () => auth()->user()?->can('transfer_student_group'))` | Action modal button is completely hidden from unauthorized employees |
| **Backend Service** | `StudentGroupTransferService.php` | In `validateTransfer()`: `if (!$this->canUserTransfer($user, $enrollment)) { throw ValidationException; }` | Throws `ValidationException` before any database queries execute |
| **API / Livewire Tampering** | Livewire State Hydration | Payload validation detects modified `group_id` without matching capability | Request aborted with 403 / Validation Error |
